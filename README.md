# РЕП — бот репутации для Telegram-групп

Бот ведёт профиль каждого участника группы: сколько сообщений он написал, когда вступил и какая у него репутация.
Репутация показывается **серой плашкой (тегом) рядом с ником**, например `реп71`. Права администратора участнику при этом не выдаются.

## Как пользоваться

- Чтобы повысить репутацию, ответьте на сообщение участника `+rep` или `+реп`. Каждый может выдать **3 +rep за 24 часа**.
- `/profile` — карточка профиля (ник, репутация, сообщения, дата входа). Можно ответом на сообщение или `/profile @username`.
- `/top` — картинка с топ-15 по репутации.
- `/help` — справка.

### Команды администратора бота

Работают только для ID из `ADMIN_IDS` (по умолчанию `1457986905`):

| Команда | Что делает |
|---|---|
| `/null` (ответом) или `/null @username` | обнуляет репутацию, снимает плашку и запрещает человеку пользоваться ботом в этом чате (выдавать и получать +rep, вызывать команды) |
| `/unnull` | снимает запрет |
| `/setrep N` (ответом) или `/setrep @username N` | устанавливает репутацию |
| `/addrep N` (ответом) или `/addrep @username N` | прибавляет N к репутации (N может быть отрицательным) |
| `/check` | проверяет, хватает ли боту прав для плашек в группе |
| `/chatid` | показывает ID группы для `ALLOWED_CHAT_ID`, работает в любой группе |

Вместо `@username` можно указать числовой ID пользователя.

## Настройка

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Запустите бота на хостинге с переменной `BOT_TOKEN` (см. «Запуск на хостинге»).
3. Добавьте бота в свою группу и **сделайте его администратором** с правом **«Управление тегами»** (`can_manage_tags`).
   Без прав администратора бот не увидит все сообщения и не сможет ставить плашки.
4. В разрешениях группы **отключите участникам право менять свой тег**, иначе любой сможет написать себе `реп999`.
5. Напишите в группе `/chatid` (от аккаунта администратора бота). Бот ответит ID группы, например `-1001234567890`.
6. Добавьте на хостинге переменную `ALLOWED_CHAT_ID` с этим ID и перезапустите бота.
7. Напишите в группе `/check`: все пункты должны быть с ✅.

### Работа только в одной группе

Бот работает **только в группе из `ALLOWED_CHAT_ID`**:
- Пока `ALLOWED_CHAT_ID` не задан, бот не работает ни в одной группе. Отвечает только на `/chatid` администратора бота, чтобы можно было узнать ID.
- В любой другой группе бот молчит. Если его туда добавят, он пишет «Этот бот работает только в своей группе» и сразу выходит.
- В личных сообщениях `/start` и `/help` работают как обычно.

Узнавайте ID **после** того, как сделали бота администратором. Обычная группа при этом может превратиться в супергруппу и получить новый ID. Если это случится позже, бот напишет в логах новый ID, который нужно указать.

Ограничения Telegram:
- Плашка — до 16 символов, без эмодзи (настраивается через `TAG_FORMAT`).
- Владельцу и администраторам группы тег поставить нельзя. Для администратора бот попробует поставить «звание», но Telegram разрешает это только для админов, назначенных самим ботом.
- Точная дата вступления известна только для тех, кто вошёл, когда бот уже был в группе. Для старых участников датой входа считается их первое сообщение при боте.

## Запуск на хостинге

Токен бота **не хранится в коде**. Бот берёт его из переменной окружения `BOT_TOKEN`, которую вы задаёте в панели хостинга. Остальные настройки необязательны, у всех есть значения по умолчанию (см. таблицу ниже).

Главное правило: **база должна лежать там, где она переживёт перезапуск**. Это постоянный диск (volume) с папкой базы или PostgreSQL через `DATABASE_URL`. Иначе репутация обнулится при каждом деплое.

> Запускайте бота **в одном экземпляре**. Если тот же токен работает где-то ещё (например, у вас на компьютере), Telegram будет выдавать ошибку `Conflict`.

### Railway

1. New Project → Deploy from GitHub repo → выберите этот репозиторий. Railway сам найдёт `Dockerfile` и `railway.json`.
2. Вкладка сервиса **Variables** → New Variable: `BOT_TOKEN` = ваш токен. Позже там же добавьте `ALLOWED_CHAT_ID` (см. «Настройка»).
3. Сохранность данных, на выбор:
   - **Volume:** правой кнопкой по сервису → Attach Volume, путь любой, например `/data`. Бот сам найдёт volume и положит туда базу.
   - **PostgreSQL:** New → Database → PostgreSQL. В Variables бота добавьте `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`.
4. Deploy. В логах должно появиться `Бот запущен: @имя_бота`.

### Render

Вариант через Blueprint (`render.yaml` уже в репозитории): New → Blueprint → выберите репозиторий. Render создаст фоновый сервис (Background Worker) и базу PostgreSQL, а `BOT_TOKEN` попросит ввести при создании.
На Render фоновые сервисы платные, а бесплатный PostgreSQL удаляется через 30 дней. Для постоянной работы выберите платный план базы.

### Свой сервер (VPS) через Docker

```bash
git clone <ссылка на репозиторий> repbot && cd repbot
cp .env.example .env
nano .env                       # впишите BOT_TOKEN=...
docker compose up -d --build
docker compose logs -f          # логи
```

База лежит в папке `data/` рядом с проектом и сохраняется при перезапуске и обновлении. Обновление: `git pull && docker compose up -d --build`.

### Свой сервер без Docker (systemd)

Инструкция в `deploy/repbot.service`. Кратко: проект в `/opt/repbot`, venv, `.env` с `BOT_TOKEN`, затем `systemctl enable --now repbot`.

### Другие хостинги (Amvera, bothost, Timeweb, PythonAnywhere и т.п.)

- Если хостинг умеет собирать Docker: используйте `Dockerfile` из репозитория и подключите постоянное хранилище к папке `/app/data`.
- Если это хостинг Python-скриптов: версия Python 3.10+, зависимости из `requirements.txt`, команда запуска `python main.py` (или `Procfile`). Папка базы — `data/` в проекте, либо укажите `DB_PATH` на постоянный диск.
- Токен впишите в раздел переменных окружения (Environment / Variables / Секреты) под именем `BOT_TOKEN`.

### Локально

```bash
pip install -r requirements.txt
cp .env.example .env   # впишите BOT_TOKEN
python main.py
```

### Если бот не запускается

| В логах | Что сделать |
|---|---|
| `Не задан токен бота` | добавьте переменную `BOT_TOKEN` в настройках хостинга |
| `BOT_TOKEN выглядит неправильно` | скопируйте токен из @BotFather целиком, без пробелов и кавычек |
| `Telegram отклонил BOT_TOKEN` | токен отозван или с опечаткой — получите актуальный в @BotFather (`/mybots` → API Token) |
| `ALLOWED_CHAT_ID не задан` или `Чат … игнорируется` | укажите ID своей группы в `ALLOWED_CHAT_ID` (узнать: `/chatid` в группе) |
| `Не удалось поставить плашку` | напишите в группе `/check` и исправьте пункты с ❌ |
| `Conflict: terminated by other getUpdates request` | бот запущен где-то ещё — остановите второй экземпляр |
| `данные пропадут при перезапуске` | подключите volume или PostgreSQL (см. выше) |

## Сохранность данных

Все данные хранятся в базе, а не в памяти: профили, репутация, сообщения, запреты, лимиты +rep. Поэтому после перезапуска ничего не теряется.

- **SQLite (по умолчанию).** Это файл `data/repbot.db`, в Docker — `/app/data/repbot.db`. Путь можно поменять через `DB_PATH`. На Railway с подключённым volume база автоматически кладётся в него.
- **PostgreSQL.** Задайте `DATABASE_URL=postgresql://...`. Если переменная задана, SQLite не используется.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен бота (**обязательно**) |
| `ALLOWED_CHAT_ID` | — | ID группы, в которой работает бот (**обязательно**, узнать: `/chatid`) |
| `ADMIN_IDS` | `1457986905` | ID администраторов бота через запятую |
| `DATABASE_URL` | — | строка подключения PostgreSQL (если задана, SQLite не используется) |
| `DB_PATH` | `data/repbot.db` | путь к файлу SQLite |
| `DAILY_REP_LIMIT` | `3` | сколько +rep можно выдать за 24 часа |
| `TAG_FORMAT` | `реп{rep}` | текст плашки |
| `TZ_NAME` | `Europe/Moscow` | часовой пояс для дат |

## Структура проекта

```
main.py               точка входа: проверка настроек, подключение к БД, запуск бота
repbot/
  config.py           чтение переменных окружения (BOT_TOKEN и др.)
  db.py               хранилище: SQLite или PostgreSQL
  handlers.py         команды и +rep
  middleware.py       подсчёт сообщений
  tags.py             серая плашка с репутацией
  avatars.py          загрузка аватарок для /top
  top_image.py        отрисовка картинки /top
fonts/                шрифты Inter и DejaVu (свободные лицензии)
Dockerfile            образ для любого Docker-хостинга
docker-compose.yml    запуск на своём сервере
railway.json          настройки Railway
render.yaml           Blueprint для Render
Procfile              команда запуска для Heroku-подобных хостингов
deploy/repbot.service systemd-сервис для VPS без Docker
.env.example          пример настроек
```
